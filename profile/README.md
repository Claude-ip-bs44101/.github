<p>问「收费标准」的人，往往已经看过好几家报价，却被口径绕晕了：有的按月按条，有的按流量，有的按并发数，还有按小时计费的。口径不同，数字没法直接比。这篇不报具体价格，而是给一份决策清单：先算清三个自己的数，再对照四种计费形式，最后用五个问题定下买的档位。接内部系统批量开号的场景会单独说，因为那类用法的结算细节和普通用户差别挺大。</p>

<h2>一、先算清自己的三个数，不然比价没意义</h2>
<h3>第一个数：峰值并发</h3>
<p>不是账号总数，是同一秒真正在发请求的数量。十个号不等于十个并发，如果操作是排队执行的，实际并发可能只有两个。查峰值最准的办法是看日志里每秒请求数，取九十五分位，别看平均值，平均值会骗你。</p>
<h3>第二个数：月流量</h3>
<p>按出口侧上下行合计估算。一次普通对话请求加上返回内容，通常几十到几百 KB，按每天两百次、每月三十天算，差不多几 GB。跑批量任务的量会大得多，一次导入动辄几十 MB，这一项要按实际任务算。</p>
<h3>第三个数：同时在线的号数</h3>
<p>这个数决定你需要几条线，而不是多少流量。一号一线是最省心的配置，能不能共用取决于你的操作强度，别为了省一条线的钱把两个号绑在一起。</p>

<h2>四、接内部系统批量开号，结算上有三个细节</h2>
<h3>别按账号数囤量</h3>
<p>内部系统批量开号，账号数是预估的，实际用起来常常只有一半活跃。按账号数囤一批线，闲置的部分照样计费。更稳的做法是按实际并发开线，业务涨了再加，服务商能按天开通的话，加线成本很低。</p>
<h3>按实际占用结算要写进约定</h3>
<p>「按实际占用结算」这句话得落到字面：占用的定义是什么，统计周期是小时还是天，不足一个单位怎么算。我见过按天计费但按小时统计、最后一小时也算一整天的算法，月底账单一出来差出三成。</p>
<h3>预留扩容通道</h3>
<p>内部系统上线初期流量往往翻倍增长，合同里最好写明扩容的响应时间，比如新增十条线多久能交付。这一条不涉及价格，但决定你业务爬坡时会不会被卡住。</p>

<p>以上为市场观察区间，仅供参考，实际以服务商当期报价为准。我自己的取舍很朴素：用量能算准就按量，算不准就按月买一条打底，超出部分按量补。这个组合的好处是账单有上限，也不会为闲置付太多。</p>
<p>最后提醒一句，别被「买一年送三个月」这类方案带节奏。线路质量会变，服务商也会变，先跑三个月再谈长约，比一次性押一年稳。</p>

<h2>常见问答</h2>
<h3>并发数可以几个人共用吗？</h3>
<p>答：可以，但要看你买的是哪种并发。如果是连接数口径，浏览器一开页面就占掉不少，几个人共用很容易超标。建议先小剂量测，看实际占用曲线，再定买多少。</p>
<h3>按流量计费会不会有隐藏上限？</h3>
<p>答：有的服务商会设单日流量上限或突发限速，超出后降速而不额外收费。这类条款通常在细则里，下单前翻一遍，问清楚超限后的处理方式。</p>
<h3>批量开号一定要先囤一批线吗？</h3>
<p>答：不必。现在多数服务商支持按天开通，业务起来再加线完全来得及。囤线的唯一好处是拿到更低单价，但如果闲置率超过三成，省下的单价抵不过闲置成本。</p>
<h3>月底账单和预期差很多，怎么查？</h3>
<p>答：先看计量口径，再看统计周期。把服务商给的明细按天拉出来，和自己的日志对一遍，重点看峰值那天。差异集中在某一天，通常是那天跑了批处理任务，属于正常；差异均匀分布，才可能是口径问题。</p>
